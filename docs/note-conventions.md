# Opt-in note conventions

These are available vault/project-local policies, not universal Markdown instructions. Apply only when the user or destination’s existing policy opts in; this document does not change any vault or project instructions.

## Summary callout

Where Obsidian callouts are supported, a `> [!summary]` after frontmatter can give the core idea and why it matters in a few sentences or short bullets. Make it stand alone, avoid duplicating the opening paragraph, and revise it when the note changes. Use ordinary prose in renderers that do not support callouts.

## Useful cross-links

Search for existing canonical pages before adding navigation links. Link once where a reader would use it; use `[[page|natural wording]]` only in a destination that supports wikilinks, standard Markdown elsewhere. Do not link every noun or invent unresolved targets unless the local policy deliberately uses them. Inline links and source/reference sections serve different jobs; either may be appropriate. Preserve existing frontmatter and naming conventions.
