# Technical UI copy humanisation

Use this reference for anti-AI passes over component demos, pattern libraries, documentation pages, and other technical UI copy.

## Audit the whole rendered document

Review every visible surface, not only body paragraphs:

- title and metadata description;
- headings and kickers;
- component inventories;
- steps and process labels;
- diagram text and captions;
- empty/error states; and
- accessibility text.

## High-signal probes

- Does the heading, paragraph, and caption restate the same insight in polished variations? Keep the clearest statement and make the other surfaces add information.
- Does a component description explain observable behaviour, constraints, or ownership, or merely rename the component in sentence form?
- Has messy implementation history been cleaned into a suspiciously inevitable methodology? Restore owned provenance and practical compromises.
- Are brochure abstractions such as “living specimen”, “visual vocabulary”, “semantic boundary”, or “escape hatch” standing in for concrete behaviour? Name what the code renders, preserves, or leaves to the caller.
- Does one grammatical trick recur across a short page—especially repeated “without …”, balanced contrasts, semicolon slogans, or tidy three-stage diagrams? Judge accumulation rather than banning isolated uses.
- Does a diagram caption add information that its title, paragraph, and labels do not already provide?

A useful revision often replaces abstract third-person claims with the concrete reason the author built the page. Leave ordinary connective prose alone. Do not add fake anecdotes, jokes, uncertainty, or roughness merely to perform humanity.

## Review cadence

Make the substantive edit first, then inspect the complete rendered result directly. Use a bounded fresh-context review only when `risk-calibrated-agent-reviews` identifies a consequential boundary that rendered inspection cannot adequately constrain. Validate any findings against the actual copy and apply only material corrections; do not repeatedly re-review wording tweaks.
