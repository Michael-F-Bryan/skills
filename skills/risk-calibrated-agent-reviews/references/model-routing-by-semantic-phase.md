# Model routing by semantic phase

For consequential API, lifecycle, and architecture work, route the abstract design seat to a stronger model first. Require a precise implementation contract before handing work to a faster coding model. Add a fresh review model only when `risk-calibrated-agent-reviews` identifies a load-bearing boundary that warrants independent judgement.

Do not assign abstract API discovery to the faster implementer merely because it will eventually write the files. Faster models perform best with a settled contract and explicit behavioural evidence.

When the user has an established coding-style or engineering-practice skill, make it an explicit source for planner, implementer, and reviewer. Replace vague adjectives such as “clean” or “elegant” with the skill's concrete ownership, abstraction, testing, and deletion standards.

When independent review is warranted:

1. Strong planner settles API, invariants, scope, and complexity stops.
2. Faster implementation owner executes the brief in an isolated worktree.
3. Fresh strong reviewer inspects the exact base/head and falsifies the named risky boundary.
4. Coordinator validates every finding against source before dispatching a focused fixer.

Do not let several workers concurrently own shared-state implementation.
